- `internal/ui/chrome/workspace_trailing.go:WorkspaceTrailing` returns the32px row. `WorkspaceTrailingTop=8` is a shell placement contract, not an additional internal margin. - `WorkspaceTrailingModel` accepts `Git *GitBadge`, `Status *git.RepositoryStatus`, `WorkspaceRoot`, `Density`, `GitLoaded`, `GitBusy`, `ManagedSession`, `HideGit`, `ChangeRequestOpen`, and `ChangeRequestShort` (default PR). - `OnGitAction func(string)` receives exactly `commit`, `commit_push`, `commit_push_pr`, `push`, `create_pr`, `pull`, `publish`, `init`, or `open_pr`. Only identical single actions can fall back to the existing GitBadge callbacks; a combined action is never approximated by silently calling a different button. `OnGitMenuOpen` is the existing status-refresh hook. No Fetch/Pull/Push/PR-panel toolbar row is added.
- `RenderBranches func(*ui.Context,ui.Element,*bool)` passes the real branch trigger and popup state to `diffsurface.CaptionBranches(c,diffModel,anchor,open)`. That adapter shares the Workbench's cancellable branch-list request, existing `beginGitOperation`, change refresh and error/progress state; its popup and create dialog never substitute opening the Diff pane for selecting a branch.
- `(*Workbench).RequestCaptionAction(root,message,action) bool` opens existing native reviews. Commit combinations preselect a single matching Prepare-review mode; they do not automatically call preparation, a model or mutation. Push and PR open the existing remote-review flows. Publish opens the existing publish review, and Initialize opens the existing non-repository gate. `pull` and `open_pr` return false for root to route to their existing callbacks. These review routes intentionally preserve the session's authorized native review boundary; they are not claims that the pinned browser's immediate stacked execution has been reproduced.
- `RenderGitActivity func(*ui.Context)` belongs outside `HideGit` and status-loading gates and can call `diffsurface.CaptionActivity(c,diffModel)` to settle the same operation and mount its existing bounded progress card as an overlay. Root must avoid drawing a duplicate progress card when the existing Diff pane also renders it. Existing review/dialog state remains in the shared window Workbench.
