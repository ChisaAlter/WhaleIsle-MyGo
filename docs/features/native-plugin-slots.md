# Native Plugins contributions

The native Plugins page consumes the live Host browser SlotRegistry through the desktop-owned `whaleisle-native-plugin-ui` overlay. The overlay is prepared in the active profile; installation packages and the reference checkout remain read-only. It reads winning registrations with `entriesOfSlot`, resolved labels, active locale and rendered summaries. Package metadata does not authorize a contribution.

The original `main` entry with key `plugins` remains the only renderer of its child slots. It supplies configuration forms, accepted Host revision, current bundle/row/item subject, injected services and Cordis disposal. The adapter never calls a contributed component, creates an injected face or invents a plugin-action RPC.

| Slot | Native integration |
| --- | --- |
| `plugins.item` | Live id, title, summary and order populate native cards. Existing mature native editors remain available; other page bodies open in a local browser seat. The page outlet is selected under `data-plugin-config`, separate from its summary outlet. |
| `plugins.bundle.config` | Exact package-key registration adds configuration to the native bundle detail. Original form/content renders in the local seat. |
| `plugins.row.config` | Exact `<package>#<patch row id>` registration exposes row configuration. Native identity keeps the patch id separate from the Loader entry id used to locate the original row control. |
| `plugins.detail.actions` | Rendered control labels and disabled states appear as native buttons. Invocation addresses a short-lived DOM handle bound to page, revision and subject, then clicks the original live control. Custom content remains accessible in the local action seat. |
| `plugins.detail.badge` | Current rendered text is displayed beside the native detail title for bundle, row and official item subjects. Rich badge interactions and artwork are not translated into native widgets. |
| `plugins.detail.section` | A contributed section opens in a local seat below the native detail content. Its internal controls and section chrome remain the original plugin's. |
| `plugins.add.actions` | The native add menu can open the original contributed add-menu content in a local seat. The original menu owner retains dismissal and action behavior. |
| `plugins.bundle.activation` | For a matching live registration, native list enable delegates one gesture to the original list switch before any native RPC. The original page commits the enable and renders its guidance in a local seat; its `onDismiss` and `onOpenDetails` remain the original callbacks. Disable and packages without this slot retain the mature native actions. |

The adapter follows `slots/changed`, locale and layout subscriptions plus DOM changes. It waits for the actual `plugins` main registration before selecting it; it does not continuously retry navigation or steal later navigation after a fulfilled request. The current original page must expose `data-plugin-item`, `data-plugin-detail`, `data-plugin-row-detail`, `data-plugin-item-detail`, `data-plugin-row`, `data-plugin-config` and the renderer's `data-slot` wrappers. Missing owners/outlets produce unavailable content rather than a replacement form or a guessed RPC. Configuration writes remain revision-aware through the original ConfigForm and Host settings service.

A single binding-free WebView uses an exact-Host gateway. The Host session cookie remains in Go upstream headers. Its independent random HttpOnly browser capability is never persisted. All native bindings and application events are disabled, redirects/navigation are constrained to the gateway, and the existing media/notification policy remains in force. Private metadata WebSocket requests pass the same cookie and origin checks as other gateway traffic; they cannot intercept built-in keyboard/module routes or arbitrary Host paths. Payloads contain slot metadata, text, control handles and state, never executable code or method names.

A browser action is accepted only for the current page, revision, selected subject and enabled handle. The browser rechecks that the node is connected and belongs to the original detail-actions outlet. Page disconnect/replacement, slot disposal, subject change and route exit discard prior metadata and handles. Host generation or cookie/origin change destroys the gateway and WebView. Hiding or minimizing the parent also destroys the capability; restoring the native Plugins page creates a fresh owner.

The local seat keeps the full DOM viewport and passes an independent native paint clip and occlusion holes to `PresentPlugin`; scrolling does not resize or reflow it. The original seat scrolls internally when content exceeds the 560 DIP native height cap. Native plugin dialogs and the add popover mask the seat; paint callbacks run in `DrawOver` so modal exclusion is applied. Windows uses a native window region, macOS uses the existing sibling browser occlusion path, and unsupported clipping fails closed with an error. The Win32 functional fixture checks both horizontal/vertical offsets, a menu hole, excluded hit-test points and the unchanged full viewport size.

Validation uses temporary owned Host profiles, a Loader-loaded third-party fixture and independent headless Chrome. It exercises live registrations, localized metadata, original detail subjects, action invocation and stale revision refusal, badge text, page configuration and section interactions, disposal, saving/restoring the real `agent-loop` form, and the original list enable → activation guidance → `onOpenDetails` workflow with a fixture registration. A separate authenticated bridge test covers page replacement, foreign/stale subject and revision refusal and capability shutdown. Tests use the hidden runner and background process helpers; no installed application, account, user workspace or model prompt is used.

The native conversation's normal title-row More menu contains “Session plugins”; there is no floating “Session plugins” button. The command stays available before an owner exists and creates the original browser owner only after a user chooses it. An empty Hero with a selected Session has the same normal More menu. Closing the local dialog collapses its seat, releases browser focus and retains the same owner for the same Session/Host/main content. The menu's “Turn off Session plugins” destroys it. Session/Host/generation or main-content changes, parent hide/minimize and exit also destroy the owner. Inactive frame synchronization reads neither a complete Session view nor registry pages, and never navigates a background browser to discover plugins.

The exact native Session id, Host generation and selection generation are captured on explicit opening. A captured navigation target rechecks them each active frame and before actions; selecting away and back to the same id does not revive old authority. The browser delegates to real `uiWorkspace.openSession`, waits for the retained binding to be open, and requires the original `data-conversation-content` occurrence to match. The original `main.conversation` owner, SessionProvider and nested slot owners render every component. The adapter does not call contributed components, rerun chain selectors or manufacture Session/Tool props.

The local picker reads winning registrations for Session header, body/view, composer/input, Chat, approval/review and Tool positions, but exposes only actual rendered entries with visible content. The Session-only exact-Host gateway matches the shipped renderer's guarded-entry dispatch and adds a keyed `display:contents` observation wrapper around its original React result. No component or election is called by the adapter. A declined chain, keyed fallback, null component or error face has no selectable contribution. Entry identity is checked against the current registry winners again on use; Tool call id and turn-tail coordinates remain attached to their original DOM occurrence. The picker displays available turn and tool-call context, with an ordinal when two visible entries otherwise match; a present turn 0 stays distinct from an unknown turn. Handles and focus remain tied to the occurrence when the list reorders, and attribution refreshes when the original DOM coordinates change. Native header controls use each actual header entry's labels/disabled state and route a gesture to that original live control in the matching actions/utilities/corner title-row zone. Complex content continues in its original local seat.

The response adapter changes no installed/vendor files and is enabled only for an explicitly opened Session gateway. It handles plain, gzip and deflate responses within a bounded buffer, preserves original renderer bytes when version or CSP prevents entry observation, and does not inject a second plugin or repeat mount effects. Without observation, “Open full conversation” remains an explicit original-page fallback; unproven wrappers never become native controls. The desktop's existing no-welcome choice is also carried into the known Models client response: automatic welcome/credential onboarding is disabled without writing acknowledgement, settings or credentials and without inventing a `dshDesktop` permission API. If that onboarding response is unrecognized, the new Session view is blocked with a version incompatibility message; it must not expose a welcome page. Page, revision, Session id, selection epoch and connected entry must still match when a control or occurrence is used.

An elected composer contribution displays the original complete composer seat. A declined chain does not expose the default composer as a plugin. Its browser draft is separate from the preserved native draft; drafts, attachment receipts, edits and submission state are not mirrored between owners. The original input owner performs its own draft persistence. Collapsing/reopening the retained seat does not unmount its components; destroying the owner follows the original browser disposal path. Plugin callbacks and admitted Host writes remain those of the original owner.

Header actions/utilities/corner have native in-place coverage after explicit activation. Completed Go transcript rows also offer “Open turn plugin” entries before their footer, including failed turns, but only when the current raw `turn/end` turn and safe integer seq uniquely match a live original `conversation.chat.turnTail` occurrence. The observation wrapper reads canonical coordinates from the original `owner.turn.data.get('turn-tail')`; `owner.seq` may address the closing Assistant and is never used as the end seq. Missing raw events, ambiguous duplicate turn/seq, unloaded history, absent owners and old Host/selection epochs produce no per-turn entry. Same-label entries retain the picker's attribution and opaque handle identity. Clicking captures page/revision/subject/handle, rechecks the current raw boundary and original owner, and opens that complete original content in the existing DialogBase. Browser acknowledgement includes a unique per-click nonce, so repeat selection cannot reuse an earlier acknowledgement; a disconnected, withdrawn or timed-out selection returns to the picker without displaying the prior outlet. This remains single-owner, single-browser local presentation: turnTail bodies are not inserted as inline WebViews into Go transcript rows. Virtualization, inactive views, pending interactions and managed composer selection can leave a registered slot without a mounted owner. The adapter does not create missing messages, tools, approvals or forms. Original built-in registrations may duplicate an equivalent existing native header occupant after activation; opaque registry registrant names do not prove package origin, so the bridge does not suppress an entry merely by id and risk hiding a legitimate override. Text/accessible controls are native projections, not a serialization of custom graphics, rich badges or arbitrary React state.

The Loader-loaded isolated Host fixture certifies no synthetic contribution when absent, declined-chain/keyed fallback refusal, null output refusal, elected complete composer, original header controls, `Session.rename` acceptance plus `useProjection('title')` echo, focus/blur on seat selection/collapse, retained reopen without duplicate mount/disposal, original draft persistence, old-page and switched-Session action refusal, registration disposal, missing-owner refusal, original full-page access without entry observation, and fresh/reloaded profiles without welcome or credential onboarding. Native tests check menu open/stop/original Launcher reachability, header-zone placement, inactive no-Snapshot behavior, explicit destruction and same-id/Host/route fences. Tests use owned temporary profiles/processes and independent Chrome; no real profile, installed process, model call or credential is used. Headless regression additionally executes the actual renderer observation prelude and Session adapter in Node, checks canonical turn-tail metadata, repeated nonce acknowledgements, stale revision/epoch and retarget refusal, and uses native ui.Tester transcript rows to exercise distinct same-label completed-turn entries, folding and failure footers. Authenticated WebSocket fixtures cover exact page dispatch, canonical seq refusal, disconnected owners and surface-handle retirement. These checks do not certify simultaneous multi-row browser rendering or native GUI interaction for turnTail. Other slot families do not have independent end-to-end certification for every plugin. Sidebar/main/settings views keep the existing full Host adapter. Host renderer changes require a matched response adapter; version incompatibility is reported without silently accepting fallback content.
