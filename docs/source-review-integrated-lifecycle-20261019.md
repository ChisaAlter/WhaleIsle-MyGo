## Confirmed findings and correction reads

1. Schedule OS minimize/hide destroyed mounted editor drafts. Main `OnHide` / `OnMinimize` called `Workspace.PauseContent(false)`; its unconditional Schedule deactivation cleared the detail drafts and pane instances. Restoring the window re-created an editor from backend data. Corrective `291b23e` now deactivates Schedule only for `pauseContent(true)` (outgoing-session suspension). The OS path retains the mounted draft; true route/frame absence, target replacement, session suspension and disposal still retire its owner. Source finding closed by reread; behavior remains unexecuted.

2. Checkpoint Retry could omit a valid snapshot. Sequence: valid A pending in the debounce window; capture failure clears pending; UI returns to exactly A; Retry fresh capture sees A's retained fingerprint and enqueues nothing. Corrective `02c6bd3` clears `hasDigest` together with pending on capture failure. A successful same-A capture consequently enqueues A again. Source finding closed by reread; prepared regression is not execution evidence.

3. An uninstaller retained in an old directory could manage a different current installation. Successful upgrade preserves unknown/locked old files and the old `Uninstall.exe`; running that old entry either retargeted the shared APP_ID registry to the partially removed old directory on failure, or deleted the current registry/shortcuts on success. Reported locations before correction: helper retry registry writes (then lines 725–727), main uninstall section lines 184–188, and retained old directory helper lines 690–703. Corrective `863ce35` adds a per-install manifest/registry identity plus original source-path ownership gate to both global-management branches. For legacy/pre-fix executable bytes, it captures the exact quoted registered uninstall path within the old installation, retires that entry to a non-`.exe` name after backup and before promotion, and restores the exact entry before restoring the old root on rollback. Thus the guard does not depend on an old executable obeying new code. Unknown/nonregistered old entries are not guessed or renamed; the correction covers the registered management entry. Source finding closed by final committed reread; actual upgrade, rollback and uninstall behavior remain unexecuted.

4. Visibility capture has a remaining native Files input boundary in the reviewed `3a3064f` snapshot. Its callback captures already committed application state without another paint, correctly retiring the pending capture timer and staging the latest detached model. However, Files `wrap.go:90` binds an ordinary `ui.TextArea` string. MyGo `ui/editor_input.go:33–55` retains a native edit in the editor buffer and only marks `nativeDirty`; `ui/value_input.go:150–166` publishes the string during the next widget build. Files then copies that bound value to its tab via `observeAutosave` / `capture`. A native edit followed by hide/minimize before that build can therefore leave `fileTabs.Export` with the prior draft. The `e64c7ed` fixture directly changes the tab draft and correctly covers committed-model capture without a later paint; it does not exercise pending native input. Reported to the integration owner; source finding remains open at this reviewed snapshot. The composer's custom DraftClient directly updates its draft and does not share this specific built-in string publication issue.

## Other source conclusions

No additional confirmed defect was found in the reviewed Question Flush/Export/binding path: Flush occurs outside the main state mutex, persistence serializes independently, and refresh uses asynchronous native dispatch. Checkpoint writers merge only desktop-owned fields, preserving the question writer's independent `QuestionDrafts`. Final capture runs on the native UI thread; the quit pause waits for the earlier disk writer without holding the main-state mutex. Timer invalidation covers the last edit when paint becomes idle. The `6755c17` source preserves the first pending record's queued time while replacing its payload: the 600 ms quiet debounce is limited by a five-second batch deadline; new captures do not postpone that deadline. A new pending record created during a running write starts a separate batch, and failures still stop automatic writes. Terminal restoration preserves drawer presentation while `terminalResumePending` prevents automatic PTY creation; explicit user terminal actions release that gate. These conclusions apply to the enumerated source snapshots, not later unrelated changes.

No additional confirmed Workflow admission defect was found: a child must have an actual authoritative identity descriptor, matching parent/child lineage and live running roster membership; missing/null/unknown identity is unavailable, and continuable admission uses that actual child mode. In-flight operations also retain client/mux/generation/token ownership.

No additional confirmed Files pagination defect was found in the reviewed scope: main file binding includes client and selected-session identity; queue results require the matching occurrence/generation; navigation advances after successful pages, clamps only after reaching EOF, retains a failed target for explicit retry, resumes canceled navigation when its tab returns, and retires stale version/Host targets. This is not an assertion about the whole Files module.
