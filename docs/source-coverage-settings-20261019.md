## 来源和覆盖等级

- `O/<包>`：`../core-recovery-runtime-rc2/vendor/deepseek-harness/packages/client/<包>/lib/client.js`，原版 rc.2 已打包客户端源码。
- `V/<插件>`：`../core-recovery-runtime-rc2/vendor/<插件>/`，原版插件源码。
- `D/<文件>`：`C:/AI/Deepseek-Harness-Desktop/src/<文件>`，只读原版桌面源码。
- Go 路径相对于当前仓库。表中同时标出 UI、生产接线或状态实现；只有名称映射不构成行为覆盖。
- `behavior-compared`：确实读过两侧所列行为的数据流、状态或请求顺序；只涵盖该行明确列出的范围，不代表整个模块的所有语义已逐条等价。
- `entrypoint-sampled`：确认入口/主要绑定或部分字段，但未把该行的完整行为链逐条对照。
- `not-reviewed`：本次没有形成该部分的行为对照；下表未知栏也会明确保留未深查部分。

“未运行”只表示缺少运行证据，不能据此写成“未实现”。提交列中的历史提交只证明对应实现差异已经提交；不自动证明回归通过。

## 账户、凭据与 profile 的明确边界

- 原版 Models 使用配置中的 `apiKeyEnv` 引用与 `credentials.describe/set/unset`，不是把账号浏览器授权、桌面凭据文件和所有 provider key 合成一种状态。Go 的 `credentialrefs` 读取 provider/reference 元数据，空值保留已存 key，`llm-pi-ai` 缺 ref 时可按路由派生并用 revision 绑定 reference。此处读的是源码协议，未读任一实际 key。
- 原版 `removeProviderProfile` 先 unset 关联 credential，再 `settings.mutate` unset profile。Go `providerprofiles.DeleteAtEpoch` 采用相同顺序，并在 Host/epoch 变化时拒绝旧确认；失败后的部分写入恢复完整语义仍需专项对照，不能从顺序相同推导全部等价。
- `internal/ui/settings/credentials.go` 是 Go 本地桌面 credentials 文件编辑入口；`referenced_credentials.go` 是 Host 引用凭据入口。两者并存不意味着所有原版 ProviderEditor/CustomProviderCard 的交互阶段已经恢复。
- 登录：原版 `BrowserLogin` preopen popup 并绑定返回 attempt，Go `accountlogin.Flow` 绑定本进程发起 attempt 并调用系统浏览器。两侧不是同一 UI 技术；仅“有 startSignIn/cancelSignIn”不足以证明 popup 受阻、返回先于响应、过期和退出再登录均等价。
- General 中 `ui-settings.enabled`、`ui-chat.transcriptView/collapseTiming/linkOpening`、`ui-conversation.busyEnter`、`visual-replies.enabled`、`session-log-deepseek.enabled` 均有 Go 显式字段入口，但每个 Host 专用贡献的校验和后果需要按模块单独审查。通用 schema renderer、分类和导航不能作为全功能完成证据。
