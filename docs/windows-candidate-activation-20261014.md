# Explicit real-Windows verification entry

The existing build scripts cannot directly activate this prepared candidate because they require a new source build. An explicit VERIFY-AND-ACTIVATE.cmd entry is now included in ../windows-portable-candidate; its Windows Node invokes candidate-tools/activate-offline-candidate.mjs. It has NOT been executed on Windows, and candidate status remains runtime_verified=false with no .runtime-staged.

The new entry first requires actual win32/x64 Node24.19.0 ABI137 and exact bundled node.exe SHA256. It restores/checks the manifest-listed internal links. A bounded child probe runs with an explicit clean environment, fresh temporary HOME/USERPROFILE/DSH_HOME/DSHD_HOME/XDG/APPDATA/TEMP, no inherited account or model environment. Network and subprocess APIs are blocked inside that probe before loading packages. It opens only an in-memory SQLite database, loads mobile node-pty, and loads actual target .node bindings without invoking model/device APIs. It never starts desktop, Host, a daemon or mobile connection.

Only successful native loading proceeds to the unchanged current-host.verify and mobile-runtime.verify gates. Host provenance keeps its original Linux sourceBuild while separately recording actual Windows native verification. Mobile gets the actual bundled Node/platform/ABI record and format2 file/link staging manifest. Pending generated records are rolled back on any failure; .runtime-staged is written only after both existing verifiers return successfully. Failure reports windows-native-verification.json with runtime_verified=false and a concrete reason. Successful native verification explicitly leaves hostStartupVerified=false and desktopUIVerified=false; it is not UI or full Host acceptance.

A necessary dependency-layout correction was made: original mobile.verify confines links to the mobile root. Mobile's 35 target packages are now physically staged under its own .target-packages/, and only mobile link targets were redirected there. This preserves that original gate instead of weakening it. Immutable data uses hardlinks in the build workspace; ordinary ZIP content remains normal files.

One static fixture confirmed Linux/incorrect ABI rejection, matching argument acceptance, and that calling activation on Linux writes no marker and leaves candidate false. Script syntax and patch applicability checked. No repeat full-tree hashing or Windows execution was done.

activation.patch adds activate-offline-candidate.mjs and verify-offline-native.mjs, and updates package-offline-candidate.mjs to include the entry/tools and self-contained mobile target package layout. Apply after portable.patch. No Go rebuild is needed. The retained portable candidate already includes these additions.
