# Composer reference activation

Original reference: `vendor/deepseek-harness/packages/client/ui-conversation/src/client/input/editor/reference-activation.ts` routes single primary activation through the live source owner without editing the draft. `ui-reference/src/client/index.ts:168-173` opens file references; `ui-skill/src/client/index.ts:202-219` resolves skill paths from its catalog. Session and folder references do not have that file-preview action.

The shipped native composer and child editor render file, skill and session references inside the text line. A draft keeps one authoritative plain-text value for sending, copying and persistence, plus validated UTF-16 occurrence ranges for its atomic references. Display shaping replaces each occurrence with one U+FFFC object whose advance reserves the chip label and remove control. The same retained paragraph supplies wrapping, selection rectangles, pointer hit testing, caret geometry, vertical navigation and native input-method bounds. The old independent chip row is limited to the legacy TextArea path; the shipped DraftClient path does not paint a second copy of the raw reference.

Left/Right cross a reference in one move; Shift extends over the complete object. Backspace/Delete and explicit native replacement ranges cannot split a reference. Copy expands selected objects to their original text, including quoted paths and canonical session IDs. Text, emoji and combining sequences keep toolkit shaping. Native typing leaves an unfinished trigger editable until a separator or a reference completion commits it; explicit insertion and text paste import complete reference tokens. IME candidates remain ordinary text, retain the stable native client across frames, and commit as one undo operation. Active composition keeps its keys and editing commands. Undo/redo snapshots include reference occurrences as well as the original text and selection.

The reference label's single primary activation routes through `composer.Model.OnOpenReference`, connected by the real frame to the existing session-owned `OnOpenDeliverable` path. That path retains current-session/Host checks and existing file preview handling. Quoted file references preserve spaces. Skill catalog projections retain their optional source path; only a matching skill with a real path opens. Unknown skills, session/folder references, malformed/stale references, noncollapsed selections and active IME composition do not open or change the draft. A separate × control removes a reference. Right click selects the whole object and opens the existing editor; applying it is undoable. Dragging from prose selects across objects; dragging a chip moves that occurrence at the destination caret in one undo operation, preserving surrounding prose and adding required separators for the plain-text reference grammar. No new RPC or file-opening protocol is added.

Saved drafts retain the original Text field and optional References metadata. Older text-only snapshots are still read using the established parser. New snapshots validate nonoverlapping ordered ranges, UTF-16 boundaries, exact token text and kind before restoration; an empty reference list preserves an unfinished editable trigger. Broken quotes, noncanonical session links and control-containing tokens remain visible ordinary text. Stale mention spans do not fall back to editing another equal token.

Validation uses the software-rendered shipped View and registered `NativeTextInputClient`, driven through actual tester key, composition, edit-command and pointer dispatch. Checks cover visible inline pixels, shared caret widths, hero/docked layouts in both themes, narrow wrapping/resizing, atomic navigation/deletion/partial replacement, raw-text clipboard copy, IME undo, pointer selection/movement, occurrence persistence and malformed input. The composer package regression suite also passes. These checks do not exercise a live Windows TSF candidate window, GPU rendering, macOS/Linux input methods, external file preview or the desktop clipboard's file/image representations; those native desktop operations remain runtime verification work.
