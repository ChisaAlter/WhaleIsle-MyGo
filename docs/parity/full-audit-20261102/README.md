**当前阶段：全量补齐已进入产品实现、整合与独立审查，尚未达到原版全部功能验收通过。** 最新实现、实际检查及未关闭依赖见 [补齐执行记录](IMPLEMENTATION.md)。以下台账保留实施前的发现状态，不能当作修复后已重验的结果；实现通过也不能反向把旧审查改成全量可用。

## 用户两组截图对应什么问题

### 顶部布局确实做错了

原安装版 `ConversationSessionHeader` 的标题/操作行与下方对话视图页签是两个层级，与用户截图一致。MyGo 把它们压入固定 48 DIP 标题栏，并用测试断言“没有下方页签行”。这不是主题或几个像素的问题，是布局合同错误，见 SH-001；窄列失去页签入口另列 SH-002。

### 工作区不能只看起来有一行

用户报告的新建对话失效保留为 WS-001，没有用测试通过覆盖。源码审查另证实，工作区身份没有贯穿全局新会话 → Host 成员关系 → 侧栏显示链路，见 WS-002。

截图中的箭头本身不能证明该行不是目录：原版也会按悬停状态替换图标。本轮未读取真实用户 profile，`ChisaBot` 对应的实际 path 未知。需要修的是已证实的身份和动作链，不能把未知原因猜成一个图标问题。

### 轨迹仍不能宣布修好

原 rc.3 “点击后下划线也不动”的原因仍未定位。旁置诊断版在 15:35:16 记录了一次真实用户点击的事件、选中值、主视图回写和下一帧，15:35:19 也记录了返回对话；这只证明该次诊断版状态切换成功，没有观察到实际下划线像素。已修复的聊天占位分支遮挡轨迹是相关缺陷，不能解释原始点击失效。见 SH-005 / SH-006 和 [固定字段日志](evidence/trajectory-tab-trace.txt)。

### 已排除的误报

- PET-003：直接只读安装版 rig manifest 后确认，原版各表情也共用 `shell.png`，撤回“原版独立九表情资源缺失”的差异结论；仍保留实际后备画面未验收的边界。
- 原版既有会话的预设 chip 也是只读，不能报成 MyGo 不能点的缺陷。
- 原版文件树也没有直接新建/重命名/删除文件入口，不能凭想象补进缺失清单。
- 普通 Project Lead cancel 已经由 Host hook 停整个 Project；缺的是专属状态/输入区及其他明确桥接，不是“只停 Lead”。
- Whale UI 内嵌资源虽标 0.3.10，但本轮比对与安装 0.3.13 没有公共组件/DSL 缺项，六个引擎逐字节相同。73 个公共组件、50 种 Genui 类型和 14 个安装 renderer 文件的静态库存已闭合，实际缺口按注册/消费/CSP 分别列出。
- 两种首次引导此前明确禁用，未报作当前功能缺失。
- Web Search 只读 settings 下“密钥仍可独立保存”的新假设已反证撤回：安装版共享 SettingsFormModel.save 也拒绝，不能只读组件注释报差距。
- 实际桌面扩展覆盖 browser builtin 的 multiple 行为，不报“原版必有多 occurrence”；dshd-remote 是资源容器，四个实际服务入口存在，不因根目录无 package.json 报缺失。
- ui-codex-sidebar 属可选包，不默认为主界面；安装版 sprite BrowserView 总开关关闭，不把它的隐藏动作扩算成默认可用功能。

## 为什么此前的“通过”没有挡住这些问题

1. **验证了可单独调用的控制器，没有验证真实生产装配。** 例如定向工作区控制器通过，不覆盖全局按钮用另一条 CreateSession 路径；GoalDock 和 MCP 添加也各有组件/控制器，却被生产 props 或入参挡住。
2. **把实现形状当成功能完成。** 同名字段没有保证 workspaceId、cwd、owner 和授权 root 的含义一致；有按钮、页面、Host 插件或 renderer，并不保证用户能触发并得到结果。
3. **局部测试使用了错误或过时的合同。** 单行顶部被测试当作目标；旧快照和粗粒度 25 项矩阵没有覆盖当前原版能力。
