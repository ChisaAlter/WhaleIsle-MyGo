# R3：当前 MyGo 与鲸屿本体的全量对照

## 判定：仍未对齐，不能作为就绪版本交付

本轮重新从原版的页面、菜单、弹窗、插件注册和实际消费者展开，不限于 R2 的 54 项。当前差距同时存在于**功能入口、数据/草稿作用域、失败恢复、布局与弹层结构**；不是换一套样式即可收尾。

**源码对照与真实窗口证据分别记录。** 新隔离候选已经编译，但两端都未启动；本轮没有取得实际窗口、窄窗、点击命中、输入法或焦点证据。两个 Computer Use 入口均报 `native pipe 不存在`，因此完整窗口对比尚未完成。

已合并 **11 个领域、332 条表面/菜单/弹层目录记录、125 条源码差异记录（P1 16、P2 99、P3 10）**。原 **758 个动作与 367 个粗项均有明确处置，未留下只移交而无人承接的索引项**。这些数不是独立页面数或独立根因数，也不是通过率。

## 接下来按这个顺序推进

1. **先闭合数据/状态合同**：附件 owner、卡片局部保存、失败保稿重读、输入业务回执、确认宿主及一次结算。
2. **再补真实入口与承载**：普通 Team、Office/Host 交付预览、接入授权、快捷键、桌宠看看。不能以 service/helper 存在签功能完成。
3. **恢复原版布局和弹层层级**：先修共享 modal/menu/popover/scroll/footer/断点，再覆盖真实消费者；不以通用字段表、整页或 Toast 代替专用界面。
4. **桌面连接恢复后，由 root 启动两端隔离副本继续对照**：使用已准备 profile，不动原版与旧预览；补 normal/narrow、长内容、弹层打开/关闭/滚动/焦点，以及原报轨迹命中证据。当前不发模型请求。正常独立 launcher 还须单独覆盖，不能由隔离单窗推定通过。

连接恢复是实窗工作的继续条件；它不阻止采用本轮已确证的源码差异。当前候选仅供对照，不是交付版。
