# Round 112 — Inspector nested tool identity and geometry

## Result

Nested tools now retain their exact CallID through the card's fallback Inspect callback, crosshair picking and forward Inspector-to-Chat reveal. A leaf uses its own call box; a parent uses its complete descendant subtree. Child picks retain the owning root Chat occurrence and its source anchor. Tall virtual items can land on a selected child's measured region instead of centering the whole root item. Child reveal unfolds transcript ancestors without opening tool argument/output bodies.

The default [executable](../../whaleisle.exe) and numbered [pass256 executable](../../whaleisle-pass256.exe) are identical, 85,293,056 bytes, SHA256 `D278D4D84BD4FA491B73B9EF89C76A01A76483D93A284BABAFE031F2B9815E48`. [Build identity](evidence/inspector-pass256-build.json) records the hashes and protected runtime custody. The overall layout, UI, function and motion parity objective remains active.

## Original behavior established before implementation

The read-only original [ToolCallTree](../../reference/electron/vendor/deepseek-harness/packages/client/ui-tool/src/client/tool/ToolCallTree.tsx) puts each call's card and recursive children inside its `data-chat-call-id` wrapper. Descendants sit outside the own-card disclosure. Collapsing a tool body therefore does not hide its subcalls, and revealing a subcall must not expand those bodies. Its [picker matching](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/pick-match.ts) takes the closest call wrapper but preserves the nearest enclosing root Chat node. Child gutters and gaps use the closest containing ancestor.

The original [forward lookup](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/dom.ts) ranks the selected CallID before containing node/root fallbacks. The original [Log matcher](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/session-log/model.ts) prioritizes an exact `tool/call`, not `tool/ptc-dispatch-start`. Consequently a nested PTC reverse pick can select the root-anchor Log row. This rule was deliberately preserved. Original Chat-node mode selects the shared root node for each nested CallID. No synthetic child Chat rows were introduced.

## Native implementation

[Tool traversal](../../internal/ui/chat/tool_lifecycle.go) registers each materialized call's full layout box with its real parent index. IDs remain opaque; indentation and displayed titles do not infer ancestry. [Geometry reduction](../../internal/ui/chat/session_inspector_tools.go) unions descendants into ancestors in reverse preorder and gives descendants pointer priority. Only branches of a painted owner enter the hit list, clipped to the main Chat viewport. The last painted preview is discarded on removal, reflow, scroll or resize. Box registration does not add wrappers to the layout or change disclosure state. Non-Inspector/text-only tool rendering avoids the extra tree/box allocation.

[Picker targets](../../internal/ui/chat/session_inspector_picker.go) override only CallID on the owner's existing target. Owner ID, root identity, source sequence and placement remain intact. The [frame fallback callback](../../internal/ui/frame/session_inspector_pane.go) now forwards `(callID, messageID, seq)` instead of dropping the first argument. Existing trajectory routing remains preferred where available; sidebar fallback retains its existing Chat-node selection behavior.

[Reveal](../../internal/ui/chat/session_inspector_reveal.go) uses the selected subtree's clipped box for an already visible target. A positive partial intersection does not scroll. For an offscreen target inside a tall root, it queues a measured owner-relative child region. A cold owner first materializes through the existing virtual-list request, then lands on that measured region, including with reduced motion. Existing quiet/settle/flash timing and global input cancellation are reused.

The toolkit [region-scrolling API](../../third_party/mygo/ui/list_motion.go) shares the existing motion controller, keyed tracking, timing, reduced motion and interruption behavior. It clamps top/height to the measured owner each layout and finishes with an owner-hinted offset request, retaining the child endpoint through neighbor remeasurement. The original whole-item scroll path is unchanged. [API documentation](../../third_party/mygo/docs/architecture.md) describes DIPs, clamps and completion behavior.

Read-only independent review found two history-update errors, both fixed before final verification. If earlier history reparents an orphan under a newly loaded ancestor, pending reveal now re-resolves the stored call request and clears the old owner-relative region. If the owner ID survives but an earlier `tool/call` replaces a result-only source, changed source sequence/event type likewise cancels the old keyed motion and re-resolves. [Regression cases](../../internal/ui/chat/session_inspector_tools_test.go) exercise pending/running reparenting and the real production HistoryStore source-key tuple. Final source review found no remaining confirmed issue in this scope.
