# Round 110 — Chat-to-Inspector reverse selection

## Result

Reverse picking now uses the current presentation's matching rules. Raw Log ranks exact tool call, explicit event anchor, last matching Assistant, Step start, Turn start, then first event in the same location. Reasoning selects the first direct reasoning block-start under that event. Chat Group ranks exact native node/part, node, group, same Step, then same Turn. Zero-valued event, Turn and Step coordinates retain their presence. A transcript header carries group identity instead of treating its displayed sequence as a message anchor.

The default native executable is pass254, 85,242,368 bytes, SHA256 `F6EB7508F140DEB8FDA0E4DDD7A8C803BBD3677C8E4F1EF86D7A52145B0BB593`. [Binary and runtime identity](evidence/inspector-pass254-build.json) verifies that the default executable equals the numbered build. The full layout/UI/function/motion parity objective remains active.

## Original rules and executed evidence

The read-only original [SessionLogModel.pick](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/session-log/model.ts#L66) selects the first exact tool/call before the first exact anchor, independently of supplied Turn/Step. Assistant fallback chooses the last Assistant message, attempt or transient event in the same Turn and optional Step. Step alone cannot locate a log entry without Turn. Missing Step broadens the scope to the whole Turn. Boundary fallback is Step, Turn, then first same-location event. RootCallID and a tool-call stream chunk do not directly substitute for an original tool/call.

[Chat node matching](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/pick-match.ts#L54) uses exact node/part, first same-node row, actual group header, same-Turn exact Step, then first same-Turn row. Absent part can match an absent-part row ahead of the first split part. Folding and visibility do not erase materialized table identities. [Current-node enrichment](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/index.ts#L61) uses an explicit node before a group's first member, never scans later members after a missing first member, overwrites node anchor/kind, and conditionally overwrites location. It does not copy the group's first member's reasoning part into the picked target.

[scripts/inspector-reference-picks.mjs](../../scripts/inspector-reference-picks.mjs) executes the installed bundle's verbatim log pick method and Chat row matcher in a Node VM. Their loaded window/row stores are supplied by the script. It independently strips types from the source method and imports the source Chat matcher, then compares results. The installed Inspector bundle hash remains `62443553c0dec20f1d1a21b02a55822877c734059ea1c18d5a414ddafac657a0`. All 181 log and 90 Chat cases agree between installed code and source. Recorded [reference identity](evidence/inspector-pass254-reference-picks.json) and [inputs/outputs](../../internal/ui/frame/testdata/inspector-picks.json) preserve this evidence. Go checks compare those outputs against native candidate ordering and part refinement.

The comparison executes original pure matching functions. It does not boot the original browser, exercise its subscriptions, or certify its complete DOM picker. Node24's built-in TypeScript stripping is verification tooling only; the native application has no new Node/tool dependency.

## Native changes

[session_inspector_pick.go](../../internal/ui/frame/session_inspector_pick.go) separates original candidate ordering from native table-to-event adaptation. Typed optional coordinates are retained; the legacy positive Seq fallback remains for existing callers. Missing/default Seq0 does not pick event0. Actual durable root keys, including retained attempt keys, pass through unchanged. Raw event parents may be Step or Turn rows, so root eligibility does not depend on having an empty parent. Known stream children are excluded from root matching; reasoning refinement requires the selected root as the child's direct parent.

The same file resolves a current native group through its first member. The [Chat picker handoff](../../internal/ui/chat/session_inspector.go#L166) and [projected Inspector rows](../../internal/ui/frame/session_inspector_pane.go#L251) now both identify transcript headers as groups. In log mode, first-member placement replaces header display metadata; in Chat Group mode, the real header itself is selected. An explicit missing node does not retry a group's later members.

Two native adaptations remain explicit. Native streaming reasoning/text are separate blocks with process-local IDs and lack the original transient frame sequence. Their actual ChatPickID block-start remains more specific than the Step fallback; borrowed ChatID forward aliases cannot hijack a reverse pick. A current preparing tool also has no raw sequence/location. Its known call identity selects a loaded tool/call, or the actual stream root carrying that call, including when it is the group's first member. Unowned call-only targets do not gain a fabricated stream anchor. These native adaptations are tested independently from the original pure matching algorithm.

[Existing consume/reveal handling](../../internal/ui/frame/session_inspector_navigation.go#L199) continues to select only loaded rows, open ancestors, retain unrelated folds, clear a filter only when it excludes the selected row, and finish the gesture without re-revealing Chat. Mode remains unchanged. No new Store subscription, Host request or persisted event is introduced.

## Remaining differences

Forward and reverse zero-coordinate and part selection now have scoped evidence, but the native Message model still differs from the original typed Assistant Step graph and complete ConversationLocation timeline. Native live blocks do not expose every original transient sequence. Multiple durable blocks with the same part select the original first direct reasoning header unless an actual live block identity is available. Nested PTC picking/per-child rectangles and the card Inspect callback's dropped child call identity remain separate gaps. Result-only and toolCallId-only data limitations are unchanged; no speculative rootCall/PTC matching was added to the original log rules.

Chat Group still presents native projected Message objects rather than the full original typed/lazy object graph, cycle-aware traversal and paging50. The hover-mask DOM picker presentation, Turn container geometry, original anchor retention across every inactive-source lifecycle, shell/tabs/caption/font/material/control layout and motion parity, performance budgets and full production Host startup/shutdown remain open. The five desktop scenarios certify the changed native handoff, not the whole product.
