## 1. 本次修复：标准模式 x +3.34 → 0.01

算术（全部取自实测矩形）：工作区 chip 结束于 652；配置里 hero 行 `Gap(3.33)` 时，preset 实测落在 **658.67**，即除行间距外还有 **+3.34** 的额外偏移（来自 preset 控件自身的外边距/内边距）；原生 preset 起点 655.33。因此把行间距从 3.33 改为 **0**：

- 修复后：652 + 0 + 3.34 = **655.34**，与原生 655.33 差 0.01 DIP；
- 测试（`workspace_parity_test.go`、`frame/hero_chip_row_test.go`）改为断言「行间距为 0」，并在注释里记录那 3.34 属于 preset 控件本身；tester 里（无 preset options 时走 fallback 行）实测 chip 结束 198.67 = preset 起点，gap 0.00。

## 2. 未修的三项：定位与方案（不在本轮硬改的原因）

1. **发送消息 y −42.67**：`composer.go` 的 hero card 为 `Padding(8,0,8,0).Gap(12)`，控制行（`Composer trailing controls`，:522）紧跟草稿；原生草稿底 470 → 发送顶 522 = **52 DIP 间距**，我方只有 10（card gap 12 − 行内 2.67）。要命中 +42.67 需把「草稿↔控制行」间距加到 52，这会同时改变卡片高度（当前 114）——必须先确认真实卡片高度，否则会破坏 round232 的 hero 高度对齐。属于**需要一次新测量 + 布局改写 + 多个 draft 高度用例更新**的改动（约 20 分钟），本轮时间盒不允许草率下手。
2. **输入框宽度 +28.67**：原生 `Edit` 盒 x=482、w=745.33，即距卡片左 12.67、右 16.36；我方 `FillWidth()` 直接铺满卡片（x=469.33、w=774），文字缩进 12 只是 padding，不缩盒子。修法是给草稿外包一层带左右 padding 的容器（12.67 / 16.36），但 `draft_presentation_test.go` 等已钉死草稿矩形，必须同步更新。
3. **大肥鱼版宽 +14**：该徽标文本用 `theme.InterfaceSize(12)` + `Padding(1,7,0,7)`（`conversation_phase.go:124`），实测 62.67 宽/20 高 vs 原生 48.67/15.33。14 DIP 的宽度差与 4.67 的高度差同时出现，说明是**字号**而非 padding 主导（padding 只占 14）。需要按字体度量定一个更小的字号（约 11）并复核行高，避免只改宽度把身高改坏。
