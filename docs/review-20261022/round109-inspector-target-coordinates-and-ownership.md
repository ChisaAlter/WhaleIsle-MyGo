# Round 109 — Inspector forward target coordinates and occurrence ownership

## Result

Inspector-to-Chat navigation retains original event coordinates, tool/root-call identities, Assistant kind and reasoning/response part until the current native Chat projection resolves the request. Exact native render IDs take precedence over shared durable Assistant IDs. Fold expansion and final landing use the same resolved native occurrence. Successful Assistant settlement can retire a live block ID before preparation, during a queued center, or during smooth scrolling without losing the owning Step and part. A painted empty occurrence is rejected and the next ranked candidate is attempted before the Chat column.

The default native executable is pass253, size85,218,304bytes, SHA256 `5C07FC713CE40C1D5E625FFA28F1E330044DF3824489415FFC5423C1B5F6C138`; [binary identity](evidence/inspector-pass253-build.json) verifies the default and numbered output are identical. This is a bounded forward-selection repair; the complete product parity objective remains active.

## Original behavior and executed comparison

The read-only original [target resolver](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/reveal-target.ts) selects a visible root tool before exact anchor, first matching node kind, nearest Step, then nearest Turn. Explicit loaded identities fill missing coordinates even when hidden; requested coordinates win. Neighbors rank Step, Turn, then Session with stable distance ties, and deduplication retains distinct part-specific and bare-node targets. [Log targets](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/session-log/chat-target.ts) preserve the owning event sequence and numeric Turn/Step presence, including zero, plus tool/root and Assistant part selectors.

[scripts/inspector-reference-targets.mjs](../../scripts/inspector-reference-targets.mjs) reads the installed Inspector client bundle, extracts its exact pure function regions into a Node VM without rewriting them, and independently imports the TypeScript source snapshot. The installed bundle SHA256 is `62443553c0dec20f1d1a21b02a55822877c734059ea1c18d5a414ddafac657a0`. All176 model candidate cases and14 log-coordinate cases agree between the installed code and source. The native resolver is compared against every ordered candidate and all optional coordinates in those recorded outputs. [Reference identity](evidence/inspector-pass253-reference-targets.json) and the [shared cases](../../internal/ui/chat/testdata/inspector-targets.json) retain inputs, outputs and hashes. This executes actual installed functions; it does not claim a browser DOM comparison.

Occurrence lookup in the original [DOM integration](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/dom.ts) prefers call identity, node plus part, any node part, root call, then group; the original [revealer](../../reference/electron/vendor/deepseek-harness/packages/experimental/session-inspector/src/client/views/chat-node/reveal.ts) continues past unusable boxes. Native lookup adapts that order to current native Message occurrences, including root ownership for nested calls. It retains exact second-text IDs instead of treating all response blocks as the same native row.

## Repaired cases

- A settled Assistant with `[reasoning,text]` or `[image,text]` no longer lets the earlier row's SourceMessageID shadow the exact canonical text ID. Selecting a second text occurrence keeps that occurrence. Selecting a visible final answer does not open an unrelated reasoning ancestor merely because both rows share the settlement sequence.
- A tool/result at seq20 for a call at seq10 no longer jumps to a nearby answer at seq21. Tool and nested-call identity resolve to the correct projected tool owner before transcript folding. Loading the older call page after a result-only window preserves that ownership.
- Durable stream children inherit the owning event target and add reasoning/response or stream tool-call identity. Retained successful live records keep those selectors while rebinding the anchor to settlement. Native process-local Assistant rows retain optional Turn/Step coordinates without fabricating a durable raw event.
- A live request carries its native lifetime explicitly. When settlement replaces the requested random block ID, the same Assistant Step rebinds it to the canonical part, including during queued and running navigation. Normal removal, binding changes and user cancellation retain the previous cancellation behavior.
- Empty painted rows, such as a Turn Delivery with no available changed-files summary, no longer prevent a nearby usable candidate from being revealed. Request-local rejected IDs are cleared on cancellation or a new gesture. Part geometry uses the actual painted native occurrence; the already-started flash remains fixed.

The pure resolver lives in [session_inspector_target.go](../../internal/ui/chat/session_inspector_target.go); source-coordinate parsing belongs to [inspector_chat_target.go](../../internal/store/session/inspector_chat_target.go). Candidate ID, alias and call lookups are indexed once per navigation request instead of scanning the entire message list for every bare-node neighbor. There is no new subscription, Host access, network request or model call.

## Limits and remaining work

The target ordering algorithm is source-matched; native Message projection still differs from the reference typed Chat node graph. In particular, the original Assistant owns one stable per-Step node while native paints separate content blocks. Candidate anchors and inferred locations come from currently available native data; a complete ConversationLocation timeline and original live anchor retention remain further work. Native occurrence adaptation does not insert original Turn-container rectangles or expose nested PTC subcard geometry. Response/reasoning use native row rectangles, not every original DOM part/group rectangle.

Reverse Chat-to-Log picking remains a separate gap: it still rejects durable sequence0 in its final lookup and does not reconstruct the reference reasoning block child for every canonical pick. The forward zero-coordinate evidence does not certify that reverse path. DOM-hover picker presentation, typed/lazy object graph/cycles/paging50, full shell/control/font/material layout, performance budgets and the previously reproduced production shutdown hang remain open. This round ran no complete production Host boot/shutdown scenario and made no new model request. The [final process record](evidence/inspector-pass253-processes.json) verifies zero remaining Round109 native fixture processes and the original ElectronPID20012/backendPID16008 still running with3080 owned by16008. Neither original process was signalled or restarted.
