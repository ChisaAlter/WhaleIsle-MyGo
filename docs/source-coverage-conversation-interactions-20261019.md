## Implemented source gaps

1. **Mount-triggered delivery reads.** A completed turn's delivery view now requests its recorded changes summary and Host desktop metadata without requiring a preliminary click. Automatic reads use an independent callback and cannot open the review pane or modal. Explicit review, preview, native open and reveal keep their captured declaration/Host authority. A missing, expired or empty summary contributes no changes-only card; explicit presentations remain separate. `2c21cc0`.

2. **Interactive visual reply lifetime.** Inline page work uses a cancelable owner lifetime rather than an unconditional 30-minute deadline. Existing session/Host/navigation/helper retirement remains in force. This preserves a mounted page's interaction state until its actual owner retires. `2c21cc0`.

3. **Question drafts survive the same supervised profile's reload.** The recovery envelope stores only explicitly bound profile-owned question drafts. Its stable owner is provided by the application, hashed in the envelope; a cookie, random port, session ID or unspecified global Host cannot substitute for that owner. Session/call identity and a question-batch fingerprint must match an actual pending Host request before restoring answers, page position or explicit waiting/editing state. Disk state creates neither a question nor an answer. Plan-review decisions are excluded. Repeated restore does not overwrite current in-memory edits; Attach/Detach retain the same profile's deferred drafts. Dedicated mutation hooks save actual edits rather than rendering frames. A serialized latest-state writer, visible save error and synchronous `FlushQuestionDraftPersistence` support final recovery checkpoints. Store implementation is `2c21cc0`; root application integration was separately committed in `531a15d` and later recovery-owner commits.

4. **HTTP success is not question acceptance.** A named live waterfall remains sending until actual Host continuation, settlement or withdrawal retires it. A continued request reuses the same draft through its separate RPC owner. Timed foreground claims stay attached until the Host closes the claim stream. Old empty baselines cannot withdraw a live request they never observed. `6c8a569`.

5. **Queue/discard observations survive delayed receipts and repaint coalescing.** `8aecd77` retained queue observations with the in-flight answer attempt and prevented a replacement continued card from resubmitting while that attempt remained unresolved. Fresh review then followed the real `session/control → producer cache → asynchronous refresh → UI snapshot` chain and found that a queued/empty pair could disappear before any paint. `d9a1372` therefore records bounded per-active-or-currently-queued-call ordinals in the session producer. Root and child snapshots clone those facts. A read-only producer reader supplies current inbox plus observations outside the interaction lock at the actual submit baseline and again before interpreting its RPC receipt. Client/epoch/attempt identity is checked after each read. The baseline also survives in the submitted marker, covering queue/discard after the receipt. Closed calls and Host resets retire the retained facts. No control callback directly mutates UI or sends another request.

6. **PTC and canonical inline file references.** Successful `tool/ptc-dispatch` mutations now participate in the recorded wire location index, including turn/step boundaries and explicit turn coordinates. `rootCallId`, projected `Message.TurnSeq` and the selected turn do not supply ownership. Root argument JSON strings and PTC argument objects retain their distinct formats. Absolute `meta.path` is the canonical target; legacy missing metadata and the original absolute-argument fallback follow source behavior. Exact targets, basenames and argument aliases participate together in ambiguity detection. Failed/read/pending/malformed mutations contribute no target. `0f4e9ea`.

7. **Recorded-file application choices.** Delivery cards and changes review read application metadata with `GET /api/present.open` or `changes.open`, retaining recorded session/sequence/index coordinates. Explicit selection sends `POST` to that same authorized route with an opaque `application` ID. Default open/reveal/application actions share the native busy owner. No path-based shell command, implicit open or new local execution path was introduced. Child-addressed actions reuse their own declaration validator. `0f4e9ea`.

8. **Historical user references and feedback.** Complete `@file`/quoted paths now use the existing file-preview route with a captured history owner. Canonical session mentions and directories display their source-defined labels; they do not invent session/folder navigation. Adjacent `session-reference` context labels are deduplicated and associated only with the immediately preceding direct message, including longest confirmed bare labels and the recall summary. Skill tokens require an actual `skill-invocation` in the same boundary-free direct-message/context batch; hot or cold catalog resolution uses the same session/catalog/root identity and exact supplied path. Cold results return to the UI thread and recheck ownership. Unknown skills do not guess a path, and subagents do not borrow the root skill opener. Recorded assistant ratings remain visible while unrelated historical actions retain hover/focus reveal. `e160cb7`, `5aad82a`, `bb5a132`.

9. **Reference-local navigation failure and retry.** `8281fd9` adds an exact completion callback to the history reference. Its modal belongs to that reference's request version and captured history owner; close, later retries and navigation retirement invalidate late failures. The waitable Host fallback uses the actual session cwd and captured Host/scope, returns unavailable/refused/error outcomes, and does not consult global `LastAction`. Root's shared callback integration is `3b4567d`. Accepted Files/media/HTML/PDF navigation is success at this boundary; later document content-loading errors remain owned by the existing preview. They are not reclassified as reference-navigation failures.

## Source distinctions retained deliberately

- Actual `SessionReference` and `FolderReference` components are non-interactive chips. Adding session/folder navigation based solely on their appearance would add behavior the source does not implement.
- The actual pending-slot constructor selects `hide` for a named question and `cancel` for an anonymous question. Named plan-review “Discuss” therefore hides rather than rejects the durable request, despite broader README wording.
- `selectProducedFiles` is consumed by `chatFileMentions.forClosing`; the registered `DeliverablesTail` claims changes announcements and explicit presentations. A comment about produced-file listing did **not** establish another missing tail-list component, so no speculative list was added.
- The original reference candidate reader waits for history open. The Go reader's different placement alone did not prove a stale request or observable missing feature. No speculative readiness gate was added in this work.
